## Замечания

Статусы: `открыто` → `исправлено (коммит)` / `не исправлено (почему)`.

### К1. ML систематически занижает общий спрос, а по умолчанию для IEK стоит ML — критично · открыто

Бэктест июль–август 2026, сумма прогноза против факта:

| | Факт | Формула | ML |
|---|---|---|---|
| IEK | 400 122 | +6,6% | **−22,9%** |
| SE | 363 824 | −3,8% | **−26,3%** |

На текущих данных ML даёт заказ IEK 98 181 шт. против 187 858 шт. по формуле, то есть на 48% меньше. Причина — `loss="absolute_error"`: модель предсказывает медиану, а при неравномерном спросе медиана ниже среднего. Поэтому WAPE и MdAPE у неё лучше, но общий объём занижен. Для заказа важен именно объём: с ML по умолчанию IEK недозаказывает ~23% спроса, то есть дефицит растёт, а кейс — про то, чтобы его сокращать. В правиле выбора из плана фазы 6 не было критерия смещения. Это пробел плана, не ошибка реализации.

Сделать:
1. `DEFAULT_FORECAST_METHODS` = формула для обоих поставщиков.
2. В `scripts/backtest.py` для каждого метода печатать смещение `Σпрогноз / Σфакт − 1`.
3. В правило выбора (`.planning/phases/06-ml-challenger/PLAN.md`, раздел «Правило выбора метода») Claude добавил третье условие: |смещение| ≤ 10%. Оно добавлено **после** находки, это указано в плане, и в README будет сказано так же.
4. В интерфейсе при выборе ML — предупреждение: «ML на истории занижает общий спрос на ~23% (IEK) и ~26% (SE); используйте для сравнения».
5. **Модель не переобучать с другой функцией потерь без решения человека.** Это был бы новый эксперимент после просмотра результатов.

### К2. Первый расчёт по умолчанию — 72 с · открыто

Замер: загрузка 28 с (отдельно, при открытии), затем по кнопке:

| Этап | Время |
|---|---|
| `prepare_forecasts` + `build_training_frame` | **47 с** |
| `train_model` | 5 с |
| `feature_importance` | 3 с |
| расчёт ML | 11 с |
| расчёт формулы | 8 с |

После К1 режим по умолчанию — формула (~8 с), и ML учится только при выборе ML. Дополнительно векторизовать `build_training_frame` (цель < 10 с), без изменения признаков: тест — таблица до и после совпадает (`pd.testing.assert_frame_equal`).

### В1. Главные колонки не видны без горизонтальной прокрутки · открыто

При ширине 1440 в таблице видны Код, Артикул, Наименование, Категория, Поставщик и частично «Рекомендуемое количество». «Срочность» и «Обоснование» (must have 5) уходят за правый край, у SE обрезано уже количество.

Сделать через `st.column_config`:
- порядок: Код 1С → Наименование → Количество → Срочность → Обоснование (широкая колонка) → Артикул → Категория;
- в таблицах, сгруппированных по поставщику, убрать колонку «Поставщик»;
- то же для вкладки «На проверку».

### С2. Важность признаков ML непонятна · открыто

Названия как в коде (`zero_share_12`, `same_month_last_year`), значения 0,04 / 0,01 ничего не говорят пользователю. Сделать: русские названия (например, «Доля месяцев без продаж за 12 мес.», «Продажи в тот же месяц год назад») и важность как доля в %.

### С3. Категории выглядят как числа · открыто

В фильтре и таблице — «1», «2», «3», «5». Показывать «SE, категория 1» и т.д. Если выбран поставщик IEK, фильтр категории скрыть: у IEK все «без категории».
