**Последний полный месяц** = месяц перед месяцем `AS_OF` (2026-08).
Неполный месяц `AS_OF` (2026-09) **никогда не входит** в базу прогноза,
тренд, сезонность и σ — только в расчёт `current_stock`.

## Модули `app/engine/`

Все расчёты — на помесячных продажах `sales_monthly` до последнего
полного месяца включительно, отрицательные значения (возвраты, 564
ячейки) обрезаются до 0.

### `segmentation.py`
По последним 12 полным месяцам:
- `regular` — продажи в ≥4 месяцах → модель;
- `sparse` — в 1–3 месяцах → min/max: `max_level` = максимум месячных
  продаж за 12 мес.; заказ = `max(0, max_level − free_stock − in_transit)`,
  округлённый до MOQ;
- `dead` — 0 продаж → не рассчитывается, в таблицу `review_needed`.

### `cleaning.py` — R4
1. На `sales_tx` по каждому SKU: `median`, `MAD` по количеству в строке;
   **`MAD_floor = max(MAD, 1)`** (иначе SKU, который всегда продаётся по
   1 шт., делит на ноль). Строка — выброс, если
   `(qty − median) / (1.4826 × MAD_floor) > 10` **и** `qty / Σqty_SKU > 0.2`.
2. **Связь с месячными продажами:** `monthly_clean(m) = max(0,
   monthly(m) − Σ qty выбросов SKU в месяце m)`.
3. Месяцы до начала транзакций (почти весь 2024 г.) выбросов на уровне
   строк не имеют — для них ограничение сверху по месячному ряду SKU:
   `min(monthly(m), median_месяцев + 5 × 1.4826 × max(MAD_месяцев, 1))`.
4. Сохранить флаги `is_outlier` / суммы исключённого по SKU — для
   обоснования.

### `stockout.py` — R3
Месяц m SKU — stockout, если `opening_stock(m) == 0` **и**
`monthly_clean(m) < 0.5 × median(monthly_clean по не-stockout месяцам)`.
Для таких месяцев: `demand(m) = max(monthly_clean(m), оценка)`, где
оценка = медиана не-stockout месяцев SKU × сезонный индекс(m) (см. ниже).
Корректировка только вверх.

### `forecast.py` — R1, R2 (только `regular`)
1. **Сезонный индекс поставщика** `S_sup(k)`, k = 1..12: по суммарным
   количествам поставщика за полные годы 2024 и 2025,
   `qty(год, k) / среднее_месячное(год)`, усреднить по годам.
2. **Сезонный индекс SKU** `S_sku(k)` — тем же способом по `demand` SKU,
   если у SKU есть продажи в обоих годах; иначе `S_sku = S_sup`.
   Итоговый `S(k) = 0.5 × S_sku(k) + 0.5 × S_sup(k)` (сжатие к индексу
   поставщика — у SKU только 2 года истории), ограничить [0.3, 3.0].
3. **Уровень** `L` = среднее за последние 12 полных месяцев от
   `demand(m) / S(k_m)` (очищенный от сезонности спрос).
4. **Рост** `g` = `Σ demand(последние 3 полных мес.) / Σ demand(те же 3
   мес. год назад)`, **год к году, не к предыдущим 3 месяцам** (иначе
   сезонный пик выглядит как рост); если знаменатель 0 → 1; ограничить
   [0.5, 2.0].
5. **Прогноз на месяц** `F(m) = L × g × S(k_m)`.

### `order.py` — R1, R6
- **Окно:** с `AS_OF` на `LT + COVERAGE_DAYS` дней вперёд.
  `demand_window = Σ по дням окна F(месяц дня) / дней_в_месяце`
  (окно захватывает 2–3 месяца — у каждого своя сезонность).
- **Страховой запас:** `SS = SERVICE_Z × σ × sqrt(LT / 30)`, σ —
  стандартное отклонение `demand` за последние 12 полных месяцев.
- `need = demand_window + SS − free_stock − in_transit`
- `qty = ceil(max(0, need) / moq) × moq`
- **Срочность:** `cover_days = (free_stock + in_transit) / (F(текущий
  месяц) / 30)`; `< LT` → «высокая», `< LT + COVERAGE_DAYS` → «средняя»,
  иначе «низкая».
- Строки с `qty == 0` в итоговый список не включаются (но доступны в
  полном расчёте для UI).

### `explain.py` — R5
Текст из компонентов, например: «Регулярный спрос: уровень 120 шт./мес.,
рост +12% г/г, сезонность окт ×1.15; исключён разовый заказ 900 шт.
(15.03.2026); 2 мес. дефицита восстановлены (+80 шт.); потребность на 54
дн. 230 + страховой 45 − остаток 30 − в пути 0 = 245 → кратность 50 →
250 шт.» Для `sparse` — отдельный шаблон с min/max.

### `pipeline.py`
`build_recommendations(data, config) -> (orders_df, review_needed_df)`.
