# Фаза 4 — README

Зависит от фаз 1–3.

## Цель

README для жюри хакатона. В README.md уже лежит промпт с требуемой
структурой (11 пунктов) — использовать его как чек-лист, не как текст
для копирования.

## Обязательно включить

- Методологию расчёта (сегментация, сезонность+тренд, stockout,
  исключение выбросов, MOQ) — кратко, по одному абзацу на модуль
  `app/engine/`.
- Отдельный раздел «Алгоритм исключения выбросов» — формула робастного
  z-score из `.planning/phases/02-engine/PLAN.md`, с примером.
- Инструкцию запуска: установка зависимостей из `requirements.txt`,
  команда запуска Streamlit, команда запуска тестов (`pytest`). Данные
  партнёра уже лежат в `data/raw/` в репозитории — жюри ничего не
  докладывает.
- Результат проверки на истории (Q1): WAPE наш / партнёра по IEK и SE
  из `scripts/backtest.py` — **как есть**, даже если наш хуже.
- Откуда взяты сроки поставки: IEK — из дат в документах «в пути»
  (медиана 24 дня), SE — допущение 35 дней.
- Ограничения текущей версии: нет отправки заказов поставщику (сознательно
  не сделано, п.9 RULE.md); срок поставки SE — допущение; текущий остаток
  IEK рассчитан без учёта сентябрьских приходов; разовые заказы
  определяются по накладной, а не по клиенту (ID клиента в данных нет);
  SKU без продаж за 12 мес. не прогнозируются.
- **Не придумывать функции и результаты, которых нет в коде** — сверить
  список функций с `.planning/REQUIREMENTS.md` перед сдачей.

- README.md обновлён (промпт в начале файла можно оставить или убрать —
  решает Codex по месту, это не функциональный код).
- Каждый пункт из промпта в README.md либо закрыт разделом, либо явно
  помечен как отсутствующий с причиной.
- Обновить `.planning/STATE.md` — все 4 фазы отмечены как готовые.
