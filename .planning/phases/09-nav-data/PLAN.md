## 9C. Загрузка выгрузок из 1С

### Модель данных

- **Общий набор компании**: загрузка одного пользователя становится
  текущей для всех. **Демо-данные партнёра** (`data/raw`) — исходный набор
  по умолчанию, при первом входе результат виден сразу.
- **Загрузка — полным комплектом по поставщику**: 5 файлов (транзакции
  продаж, продажи по месяцам, остатки по месяцам, товар в пути, MOQ).
  Загрузка IEK не трогает SE и наоборот. Файл «Сезонность» — необязательный,
  игнорируется (как и сейчас).
- **Тип файла определяется по содержимому (заголовкам), не по имени** —
  можно перетащить все 5 файлов разом, в любом порядке.

### Хранение

- `db/migrations/003_datasets.sql`:
  ```sql
  CREATE TABLE IF NOT EXISTS datasets (
      id          BIGSERIAL PRIMARY KEY,
      supplier    TEXT        NOT NULL CHECK (supplier IN ('IEK', 'SE')),
      uploaded_by BIGINT      REFERENCES users(id),
      uploaded_at TIMESTAMPTZ NOT NULL DEFAULT now(),
      data_as_of  DATE        NOT NULL,        -- max дата транзакций
      storage_dir TEXT        NOT NULL,        -- каталог с файлами в томе
      files       JSONB       NOT NULL,        -- тип → имя, размер, строк
      is_current  BOOLEAN     NOT NULL DEFAULT false
  );
  CREATE UNIQUE INDEX IF NOT EXISTS datasets_one_current
      ON datasets (supplier) WHERE is_current;
  ```
  Демо-набор — не строка в таблице: если для поставщика нет текущей
  загрузки, берётся `data/raw`.
- Файлы — в каталоге `UPLOAD_DIR` (по умолчанию `/app/uploads`), в
  `docker-compose.yml` — том `uploads:/app/uploads`. Имена файлов на диске
  генерировать (`<dataset_id>/<тип>.xlsx`), исходное имя — только в `files`.
- **Права:** приложение в контейнере работает от пользователя `app`. В
  `Dockerfile` до `USER app`: `RUN mkdir -p /app/uploads && chown app:app /app/uploads` —
  иначе именованный том смонтируется от root и запись упадёт. Проверить
  загрузкой внутри контейнера, а не только на хосте.

### Проверка при загрузке (`app/datasets.py`, без Streamlit)

1. Определить тип каждого файла по заголовкам; неизвестный файл → ошибка.
2. Все 5 типов на месте, без дублей.
3. Прочитать загрузчиком поставщика (`app/loaders/iek.py` / `se.py`) во
   временном каталоге; любое исключение → понятная ошибка **по файлу**
   («Остатки: не найдена колонка „Номенклатура.Код“»).
4. Санитарные проверки: есть строки продаж; коды SKU пересекаются между
   продажами и остатками (≥ 50%); дата среза определяется.
5. Только если всё прошло — файлы переносятся в `UPLOAD_DIR`, запись в
   `datasets`, `is_current` переключается в одной транзакции.
- Ограничение размера — `[server] maxUploadSize = 50` (МБ) в
  `.streamlit/config.toml`; только `.xlsx`.
- Модель данных для расчёта — объединение текущих наборов IEK и SE;
  кэш (`st.cache_data` и дисковый кэш из 8D) — **по id текущих наборов**,
  а не по хэшу `data/raw`.

### Страница «Данные»

- Две карточки — IEK и SE: источник («Демо-данные» / «Загружено <кем>
  <когда>»), дата среза, SKU, строк продаж.
- Зона загрузки: выбор поставщика + `st.file_uploader(accept_multiple_files=True, type="xlsx")`
  + кнопка «Проверить и загрузить». Результат проверки — список по файлам:
  ✓ тип определён / ✗ ошибка одной строкой.
- История загрузок: таблица (поставщик, кто, когда, дата среза) и действие
  «Сделать текущим» для отката; «Вернуть демо-данные».
- После смены набора — расчёт на странице «Заказ» пересчитывается
  автоматически (кэш по id набора).
- Утверждённый заказ запоминает, по какому набору посчитан:
  `purchase_orders.dataset_ids JSONB` (миграция 003).
