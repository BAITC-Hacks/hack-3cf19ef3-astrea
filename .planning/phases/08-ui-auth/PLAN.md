## 8A. Вход и регистрация (обязательно, делать первым)

### Схема (`db/migrations/002_users.sql`, применяется в `ensure_schema()`)

```sql
CREATE TABLE IF NOT EXISTS users (
    id            BIGSERIAL PRIMARY KEY,
    email         TEXT        NOT NULL UNIQUE,   -- хранить в нижнем регистре
    full_name     TEXT        NOT NULL,
    password_hash TEXT        NOT NULL,          -- scrypt$n$r$p$salt_hex$hash_hex
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    last_login_at TIMESTAMPTZ
);
ALTER TABLE purchase_orders ADD COLUMN IF NOT EXISTS approved_by_user_id BIGINT REFERENCES users(id);
```

### Модуль `app/auth.py` (без Streamlit, тестируется без базы где возможно)

- `hash_password(pw) -> str`: `hashlib.scrypt(n=2**14, r=8, p=1, dklen=32)`,
  соль `secrets.token_bytes(16)`; формат строки — как в схеме.
- `verify_password(pw, stored) -> bool` через `hmac.compare_digest`.
- `register(email, full_name, password, invite_code)`:
  - код сравнивается с `INVITE_CODE` из окружения через `hmac.compare_digest`;
    если `INVITE_CODE` не задан — **регистрация закрыта** (не открыта!);
  - email — валидный формат, приводится к нижнему регистру; пароль ≥ 8 символов;
  - понятные ошибки: «Неверный код приглашения», «Такой email уже есть».
- `authenticate(email, password) -> user | None`; обновляет `last_login_at`.
  Одинаковое сообщение при неверном email и неверном пароле («Неверный email
  или пароль»). После 5 неудачных попыток в сессии — пауза 30 с.

### Поведение приложения

- **Без входа не загружается и не показывается ничего из данных партнёра**:
  `load_data()` и расчёт вызываются только после успешного входа.
- Вход держится в `st.session_state`. Обновление страницы (F5) требует войти
  заново — это известное ограничение Streamlit без внешних зависимостей,
  указать в README.
- «Кто утверждает» — **текущий пользователь** (`full_name` + `approved_by_user_id`),
  поле ввода убрать.
- Если база недоступна — вход невозможен; показать экран «Сервис временно
  недоступен», без данных.

### Экран входа

Внешний вид — по `taste-skill` (см. 8B). Содержимое: «Astrea AI»,
подзаголовок одной строкой «Автозаказ поставщикам», переключатель «Вход /
Регистрация». Вход: email, пароль, кнопка. Регистрация: имя, email,
пароль, код приглашения, кнопка. Никакого другого текста.

### Деплой

- `.env.example`: `INVITE_CODE=` (пусто = регистрация закрыта) с комментарием.
- После 8A общий пароль Caddy **убирается** (два входа подряд — плохо):

## 8B. Редизайн и меньше текста

**Дизайн решает Codex через скилл `taste-skill`** (решение человека
2026-09-23): сначала аудит текущего интерфейса по скиллу, затем
направление и визуальная система. Ограничение скилла: он рассчитан на
лендинги и редизайны, «не на дашборды и таблицы» — поэтому для экрана
входа и общего стиля опираться на скилл, а для таблицы заказа и панели
деталей — на обязательные требования ниже. Реализация — в рамках
Streamlit: тема в `.streamlit/config.toml` + CSS в `app/ui/theme.py`.
Сторонние компоненты и новые зависимости не добавлять.

### Обязательные требования (не зависят от выбранного дизайна)

- Бренд — «Astrea AI», подзаголовок «Автозаказ поставщикам».
- Стандартные header/footer/меню Streamlit скрыты.
- **В таблице заказа нет колонки «Обоснование».** Обоснование — по выбору
  строки, в отдельной панели «Почему N шт.»: 5–7 коротких пунктов с
  числами из структурных полей (`level`, `growth`, `seasonal_index`,
  `excluded_outlier_qty`, `stockout_added_qty`, `demand_window`,
  `safety_stock`, `free_stock`, `in_transit`, `moq`); пустые пункты не
  показывать. Там же — правка количества, комментарий и «Остаток сверен
  с 1С» (только для `stock_unknown`); это заменяет `st.data_editor`,
  черновики правок — в `session_state`, как сейчас.
- Срочность — короткая метка (одно слово + цвет или эмодзи), не фраза.
- Сводка из 4 чисел: позиций, штук, срочно, сверить остаток.
- Параметры расчёта (сроки, покрытие, прирост, метод) спрятаны (поповер,
  раскрывающийся блок или аналог) — по умолчанию не занимают экран.
  Пояснения к полям — только через `help=`. Предупреждение про ML — внутри,
  одной строкой. Важность признаков ML — там же, только при методе ML.
- Вкладки: «Заказ», «Без продаж», «История». В «Без продаж» нет колонки
  «Причина».
- «Утвердить заказ <поставщик>» и «Скачать xlsx» рядом; итог правок одной
  строкой.
- На 1440×900 основная таблица без горизонтальной прокрутки.

### Правила текста (проверяются на ревью)

- На основном экране нет ни одного `st.caption` длиннее одной строки и нет
  абзацев. Пояснения — через `help=`.
- Удалить: «Расчёт выполняется локально…», подписи про источники сроков
  поставки под полями (перенести в `help=`), «Жёлтым выделены…», «На
  отдельный лист … ушло позиций» (эта цифра уже есть в сводке).
- Сообщения об ошибках и успехе — одна строка.

### Код

Разбить `app/ui/streamlit_app.py` (866 строк) на модули без изменения
логики расчёта:
`app/ui/theme.py`, `app/ui/auth_view.py`, `app/ui/order_view.py`
(таблица + детали + утверждение), `app/ui/history_view.py`,
`app/ui/settings_view.py`; `streamlit_app.py` — только сборка страницы.
В `app/auth.py`, `app/orders.py`, `app/db.py`, `app/engine/*` нет `import streamlit`.
