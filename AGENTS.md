# AGENTS.md

Правила работы ИИ-агентов (Claude Code и Codex) в этом репозитории.
Здесь только роли, этапы и скиллы. Всё о самом проекте — в README.md.

## Перед началом любой задачи

1. Прочитай `README.md`: стек, команды, структура, соглашения.
2. Прочитай этот файл целиком.
3. Определи текущий этап (ниже) и свою роль на нём.
   Используй только скиллы, указанные для этого этапа.

## Роли

**Claude Code — стратег, архитектор, ревьюер.**
Проверка идеи, планирование через GSD, ревью, продающие тексты.
Не пишет продуктовый код, если человек не попросил явно.

**Codex — разработчик.**
Реализация по плану GSD, тесты, упрощение кода через PonyTail, исправление замечаний.
Не меняет план и не расширяет задачу без согласования.

**Человек** — принимает решение GO/NO-GO по идее, утверждает план, мержит.

## Этапы и скиллы

| # | Этап | Кто | Скиллы | Результат |
|---|------|-----|--------|-----------|
| 0 | Проверка идеи | Claude | `idea-gate` (ProofPilot) | `docs/validation.md`, решение GO/NO-GO |
| 1 | Планирование | Claude | GSD (планирование) | план в `.planning/` |
| 2 | Реализация | Codex | GSD (исполнение и проверка), `run-checks` | рабочий код, тесты проходят |
| 3 | Упрощение | Codex | `simplify-pass` (PonyTail), `run-checks` | тот же функционал, меньше кода |
| 4 | Ревью | Claude | `review-changes`, `run-checks` | `REVIEW.md` |
| 5 | Исправления | Codex | `fix-review`, `run-checks` | закрытый `REVIEW.md` |
| 6 | Продажи | Claude | ProofPilot (продающее письмо) | `docs/outreach/` |

RTK работает на всех этапах у обоих агентов (см. ниже).

## Правила для каждого скилла

### ProofPilot — проверка идеи и продающие письма
- Используется только на этапах 0 и 6, только Claude.
- При проверке идеи подавай её нейтрально, как чужую идею на оценку,
  а не как идею человека. Нужна честная оценка, а не поддержка.
- Этап 1 не начинается без явного GO от человека в `docs/validation.md`.
- Продающие письма пишутся только после того, как продукт работает (этап 6),
  и не содержат обещаний, которых нет в `docs/validation.md` и в коде.

### GSD — планирование, разработка, тесты
- Основной движок разработки. Планирование (этап 1) запускает Claude,
  исполнение и проверку фаз (этап 2) — Codex.
- Файлы планирования GSD (`.planning/`) — единственный источник правды о плане.
  Не дублируй план в других файлах.
- Claude создаёт план в `.planning/`, но не коммитит его; Codex коммитит план в `main` и начинает работу.
- На этапах 1–2 PonyTail должен быть выключен (`/ponytail off`, в Codex — через `@ponytail`).

### PonyTail — упрощение кода
- Конфликтует с GSD, поэтому никогда не работает одновременно с ним.
- Включается только на этапе 3, после того как фаза GSD завершена и все тесты зелёные.
- Используется только через скилл `simplify-pass`.
- После этапа 3 снова выключается.

### RTK — экономия токенов
- Установлен у обоих агентов и работает автоматически через хуки.
- Не отключай и не обходи его без причины.
- Если сжатый вывод команды скрыл нужную информацию (например, полный текст ошибки),
  запусти команду повторно без RTK и упомяни это в отчёте.

## Файлы координации

- `docs/validation.md` — результат проверки идеи и решение GO/NO-GO.
- `.planning/` — план и состояние GSD.
- `REVIEW.md` — замечания ревью. Пишет Claude, закрывает Codex.

Документы (`docs/`, `.planning/`, `REVIEW.md`) создаёт и правит Claude.
Codex их читает, но не переписывает. Исключения: отметки состояния
в `.planning/STATE.md` и статусы замечаний в `REVIEW.md`.

## Общие правила

- Агенты работают по очереди в одной рабочей директории, никогда одновременно.
- Не редактируй файлы вне своей зоны ответственности на текущем этапе.
- Если что-то неясно или противоречит README — остановись и спроси.
- Вся работа идёт в ветке `main`. Другие ветки не создаются — экономим время.
- Коммитит только Codex. Claude оставляет свои изменения незакоммиченными в рабочей
  директории. Перед началом своей работы Codex коммитит их отдельным коммитом `docs:`.
- Коммиты: во время работы GSD — как делает GSD; в остальное время —
  Conventional Commits (`feat:`, `fix:`, `refactor:`, `test:`, `docs:`, `chore:`).

## Нельзя без согласования с человеком

- Добавлять или обновлять зависимости.
- Менять схему БД и существующие миграции.
- Изменять CI/CD, конфиги деплоя, файлы окружения.
- Удалять файлы или делать рефакторинг вне текущей задачи.
- Делать force push, переписывать историю.
- Добавлять секреты, ключи и токены в код.
- Отправлять письма или что-либо публиковать от имени человека.

## Готово, когда

1. Все проверки из `run-checks` проходят.
2. Новый код покрыт тестами.
3. Этап 3 (упрощение) пройден, тесты по-прежнему зелёные.
4. Замечания в `REVIEW.md` закрыты.
5. В диффе нет изменений вне задачи.
